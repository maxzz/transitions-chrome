Yes. The two panes are the same Mermaid source. Cursor’s preview is using a graph layout (often ELK), so cycles turn into that loose, curved network. The other preview uses Dagre, which ranks nodes left-to-right.

This diagram has loops (`SW → Client → Bridge → SW` and `SW → Editor → Client`), so a layout engine that treats it as a free graph will never look like a straight chain. Dagre keeps it in ranks and only curves the back-edges.

I pinned Dagre on that block in `assets/docs/2026.09.12.26, 2, extension_worlds.md`:

```mermaid
---
config:
  layout: dagre
  flowchart:
    curve: linear
    wrappingWidth: 220
---
flowchart LR
```

Reopen or refresh the left preview. It should sit in a horizontal row like the right pane, with return arrows looping back.

You will not get a pixel-identical match — Cursor and the other renderer ship different Mermaid versions — but the structure should match. I’ll check how Cursor renders Mermaid in chat versus the markdown preview, and whether that same engine can be used on the left.

You cannot point the left markdown preview at the same engine Cursor uses in chat. Those are two different renderers, and there is no setting or extension that swaps them.

**Chat / Composer / Plans** use Cursor’s in-app Mermaid (the one you like). **A normal `.md` preview** uses VS Code’s preview plus whatever Mermaid plugin is attached. Changing the diagram source will not make those two match.

Cursor staff have the same request open: [Enable Plan-style Mermaid rendering for regular .md files](https://forum.cursor.com/t/feature-request-enable-plan-style-mermaid-rendering-for-regular-md-files/148067). There is no ETA.

**Closest options**

| Goal | What to use |
| --- | --- |
| Same engine as chat | Not available for project `.md` files. The only unofficial trick is a `.plan.md` under `.cursor/plans/`, which is the Plan viewer, not a docs workflow. |
| Replace the left preview (classic left-to-right Dagre, closer to GitHub) | [Markdown Preview Mermaid Support](https://marketplace.visualstudio.com/items?itemName=bierner.markdown-mermaid) (`bierner.markdown-mermaid`). It is marked deprecated because VS Code merged Mermaid later; it still works in Cursor. If it fights Cursor’s built-in preview, run **Markdown: Open Preview** from that extension instead of `Ctrl+Shift+V`. |
| Interactive pan/zoom without chat | [Mermaid Preview](https://marketplace.visualstudio.com/items?itemName=MermaidChart.vscode-mermaid-preview) / Mermaid Chart. You click **Edit** on a fence and get a dedicated preview. Extra clicks; not the chat renderer. |

For your split view: install `bierner.markdown-mermaid`, reload the window, and open that extension’s preview on `extension_worlds.md`. That is the practical way to make the file pane look like the clean linear diagram. It still will not be the chat engine.

If you want that chat renderer on ordinary docs, the path is the forum request above — an extension cannot hook it.
